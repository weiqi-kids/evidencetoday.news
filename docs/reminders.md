**每次 session 啟動時掃這份**：今天 ≥ 到期日的項目要主動提醒使用者；未到期的不要提（避免噪音）。

規則：
- 這裡只放「到了某一天要做某件事」，**不放判斷用的數字基準**——基準會過期，到期時一律現場跑指令取得當下數據。
- 做完就把該列移到「已結案」並註明結論落在哪份文件，不要刪掉（保留決策軌跡）。
- 日期一律台灣時間（UTC+8）。

## 待補：69 篇文章的 coverAlt（無到期日，遇到能看圖的環境就做）

`pnpm check:site` 每次都會提醒目前的缺口數字（不要把數字寫進這份文件）。

**為什麼還沒做**：封面多半是 Pexels／Unsplash 外連，**遠端** agent 環境對外連圖床是
`403 connect_rejected`（組織網路政策，不可繞過）。alt 要寫得對，得先看得到那張圖。

**但這不是全環境都做不到（2026-08-17 更正）**：Windows 本機（`e:\Noah\ET`）實測
`images.unsplash.com` / `images.pexels.com` 皆回 200，`curl` 下載後用 Read 工具可直接看圖，
當天已用這個方式替 20 篇新稿逐張看圖寫完 `coverAlt`。所以這條的正確描述是
「遠端 agent 做不到、本機做得到」，不是「沒有環境做得到」——要清這 69 篇的欠帳，
在本機開 session 跑即可，做法見 `playbooks/editor-images.md`。

**為什麼不把它做成擋 build 的規則**：必填但不檢查正確性，結果就是大家隨便填一個值讓 gate
過——2026-08-07 的闢謠封面圖事件（74 篇填了不相干的圖）正是這樣來的。
見 `docs/pitfalls.md`「要求有值而不要求值正確，比沒有要求更糟」。

**做的時候要注意**：Article.astro 在缺 `coverAlt` 時退回用文章標題當 alt。那不是圖片描述，
是標題——螢幕閱讀器聽到的等於沒有說明圖裡有什麼。所以 gate 把「alt 等於 h1」也算缺漏。

**順帶要判斷的**：補 alt 的同時就能檢查圖文是否相符。本輪用文字比對做過一次粗篩，
結論是那個方法不可用——中文的「白內障」與「視力度數」沒有共同字元，字元重疊率會把
正確的配圖判成不相關。抽查有 alt 的幾篇（膽鹼→雞蛋、膠原蛋白→大骨湯、白內障→驗光試鏡架）
配圖都切題。圖文相關性只能靠人看，不要再嘗試用文字相似度自動判斷。
