# 頁面規則：短影音（/videos）

資料來源：YouTube API 產生的 `youtube-shorts.json`（`pnpm sync:youtube`，`prebuild` 會自動跑）。

---

## 列表頁 `/videos/`

- 版面順序固定：Hero → 統計卡片 → 精選短影音整理 → 分類標籤 → 所有短影音列表。
- **分類標籤放在精選短影音整理之後**，並維持 `data-category` 篩選與數量同步。
- 精選區第一張為「製作健康短影音的初衷」，後續高流量作品以展開卡片呈現（縮圖、標題、摘要、站內觀看整理連結）。
- 一般列表卡片**只保留三項**：YouTube Shorts 內嵌播放器（`embedUrl`）、影片標題、發布日期。
- **不顯示「在 YouTube 觀看」外部連結**，以維持卡片資訊一致與版面簡潔。
- YouTube 影片列表仍可顯示全部影片。

## 分類

- 短影音分類由 `src/utils/videos.ts` 依標題自動判斷。
- 自動分類不準時，用 `VIDEO_CATEGORY_OVERRIDES` 以 YouTube video id 手動指定，**不要改判斷邏輯去遷就單支影片**。

## 單頁 `/videos/[slug]/`

- **不需要所有 Shorts 都有站內頁**；只有精選或需要 AEO 的影片才建立內容頁（站內頁優先服務 SEO / AEO 與精選內容整理）。
- 有站內頁的影片需包含：YouTube 影片、重點摘要、30 秒重點、文字摘要、逐字稿、延伸閱讀。
- 前台摘要標題用「**重點摘要**」，不要用「可引用答案」當視覺標題。
- `transcript` 可放完整逐字稿，前台以 `details` 預設收合。
- **references 不可憑空新增**；沒有可靠來源時省略。
- `relatedArticles` / `relatedMyths` / `relatedIngredients` / `relatedPodcasts` 必須連到**實際存在**的內容。

## 為什麼短影音頁 Google 一頁都不收（2026-08-08 查證）

`pnpm index:coverage`：**videos 0/6 已索引**，是全站唯一整型歸零的頁型。對照組
myths 49/60、articles 83/109。查下去有兩層原因，兩層都要知道，因為只修一層會把問題換個形式。

**第一層：版型造成的重複。** 詳情頁的「繼續看短影音」用完整卡片印出另外 3 支影片的
`tldr`。整個 collection 只有 5 支的時候，這等於每頁都帶著其他頁大部分的文字——實測
5 頁彼此重複 **43.8%**（myths 對照組 23.1%）。已改成 `compact` 模式（只留縮圖與標題）。

**第二層：頁面本來就太薄，而且沒有藏起來的內容可以救。** 修完重複後每頁正文剩
**577 字**（原 764）。逐欄清點 frontmatter 之後可以確定，這不是「有內容沒渲染」：

- `description` 58 字、`tldr` 52、`aiAnswer` 65、`quickAnswer` 29、`citationAnswer` 50
  ——**這五欄講的是同一件事的五種說法**，不是五份內容。
- `transcript` 159 字（60 秒影片的逐字稿就是這個長度）。
- `evidenceBasis`／`targetAudience` 是跨篇填一樣的樣板（5 篇的 targetAudience 全是
  「一般健康教育讀者」）。

也就是說每支影片真正的獨有內容大約 200 字。**不要為了衝索引去灌水**——那會製造
AI 味與樣板，代價比沒被索引更大。

**兩條可走的路（尚未決定，需要人判斷）：**
1. 接受短影音頁不被單獨索引，把它定位成 YouTube 流量的落地頁與站內導流點，不追求搜尋曝光。
2. 改成「一個主題一頁、收數支影片」，讓單頁有足夠內容量；代價是 URL 結構要改、既有連結要轉址。

`pnpm check:site` 現在會持續回報 這兩個數字（重複率、正文中位數），不用再靠人記得去查。
