# Playbook：健康專題（topic hubs）

> 前台名稱「健康專題」。把同一主題的文章、闢謠、成分解析、Podcast、短影音、趨勢整理在一起，
> 建立 hub↔spoke 內鏈結構，利於讀者建立完整理解，也利於搜尋引擎/AI 認識主題權威（GEO）。

## 鎖定參數（改這些）

| 檔案 | 角色 |
|---|---|
| `src/data/topics.ts` | 主題定義（唯一真相）：`slug` / `name` / `intro` / `thirtySecond` / `matchKeywords` / `faq` |
| `src/utils/topic-cover.ts` | `resolveTopicCover()`：從主題自動歸入的內容取代表縮圖（見「專題卡片縮圖」） |
| `src/pages/topics/index.astro` | `/topics/` 列表頁（CollectionPage + ItemList JSON-LD；卡片帶代表縮圖） |
| `src/pages/topics/[slug].astro` | 各主題頁，依 `matchKeywords` 自動收斂內容 + FAQPage JSON-LD |
| `src/pages/index.astro` | 首頁「健康專題」區塊（讀 `TOPICS` 渲染卡片，同帶代表縮圖） |
| `src/components/blocks/Footer.astro` | 頁尾「健康專題」連結 |
| `src/components/blocks/TopNav.astro` | 導覽列「健康專題」→ `/topics/`（全站內鏈入口） |
| `src/pages/articles/[slug].astro` | 文章頁 spoke→hub 回鏈：用 `matchesTopic()` 自動列出「所屬健康專題」 |
| `src/pages/ingredients/[slug].astro` | 成分頁 spoke→hub 回鏈（同上），外加 `getAutoRelated()` tag 重疊自動補相關內容 |

### 目前的 hubs（11 個）
`omega-3` / `lutein` / `calcium-vitamin-d` / `supplement-guide` / `blood-lipids` / `blood-sugar` / `liver-kidney-test`，
以及 2026-07-12 新增：`sleep`（睡眠與助眠）/ `womens-health`（更年期與女性健康）/ `sports-nutrition`（運動營養與肌肉）/ `gut-health`（腸道健康與菌相）。
新增這四個是為了補「已達 5+ 篇卻沒有 pillar page 的最大內容群」，其中睡眠是站上最大叢集。

### hub↔spoke 雙向內鏈
- **hub→spoke**：`/topics/<slug>/` 依 `matchKeywords` 自動收斂內容（既有機制）。
- **spoke→hub**：文章單篇頁（`articles/[slug].astro`）與成分頁（`ingredients/[slug].astro`）用同一個 `matchesTopic()` 反查本文所屬專題，渲染「所屬健康專題」膠囊連結；零手工維護、新內容自動生效。

#### 2026-08-04 擴充：11 → 16 個 hub

盤點發現 **41/122 文章、51/70 闢謠命中不到任何主題**，長尾等於沒有入口頁。處理方式：

**① 新增 5 個 hub**（`food-safety` 食品安全與加工食品／`weight-management` 體重管理與減重／`immunity-cold` 免疫、過敏與感冒／`joint-bone` 關節與骨骼／`tcm-traditional` 中醫、中藥與草本）。

**選題方法（沿用此法，別憑直覺開 hub）**：先用候選關鍵字對全站語料試跑，統計各 collection 命中數，**確認常青內容（文章＋闢謠＋成分）達 15 篇以上才建立**，避免空殼 hub。刻意**未**建立「疲勞」「壓力情緒」「慢性發炎」——台灣搜尋需求雖高，但站內常青內容太薄（慢性發炎 20 篇中 13 篇是成分頁、疲勞只有 3 篇文章），且與 `sleep` 高度重疊，硬建會兩邊稀釋。這三個主題應**先補內容、再建 hub**。

**② 擴充 `lutein` 關鍵字**：原本只涵蓋補充成分，漏掉白內障、青光眼、數位眼疲勞等眼睛疾病文章。眼睛主題的讀者需求是「眼睛怎麼了」而非「該吃什麼」。

**③ 調高 `topics/[slug].astro` 的 slice 上限**（6/4/4/4/2/4 → 12/10/10/6/3/6）。hub 收得到卻不顯示等於白收；`news` 刻意維持較低，避免時效內容排擠常青內容的曝光。

成果：16 個 hub 各有 15–31 條出鏈；成分頁專題回鏈 **0 → 45/45（100%）**。

#### ⚠️ 新增／放寬關鍵字後必做：中文子字串誤命中檢查

中文沒有詞界，`matchKeywords` 用的是 `includes()`，**子字串碰撞是這裡最常見的 bug**。2026-08-04 實際踩到三個：

| 關鍵字 | 誤命中 | 處置 |
|---|---|---|
| `代糖` | 「取**代糖**尿病藥」（秋葵水降血糖） | 移除，甜味劑題材改由 `甜味劑` 收 |
| `抗體` | 偏頭痛的單株**抗體**用藥、甲狀腺**抗體** | 移除 |
| `體質` | 「酸鹼**體質**」這類與中醫無關的偽科學 | 移除 |

另外 `致癌`、`咳嗽`、`喉嚨` 這類**泛症狀詞**會跨主題亂抓（防曬乳致癌被收進食品安全、胃食道逆流的慢性咳被收進免疫），一律不收，改用該主題專屬的具體詞。

**驗證方法**：改完關鍵字後，逐一列出每個 hub 收到的內容標題與「是哪個關鍵字命中的」，確認同質性。診斷腳本很短，照下列邏輯重寫即可：對每篇內容取 `title + tags + topicTags` 轉小寫，列出 `matchKeywords` 中所有命中的詞，人工掃一遍明顯不對的項目。

#### 成分頁的孤島問題（2026-08-04 修）

成分頁絕大多數沒填 `relatedX`，渲染出空的相關區、對外零出鏈，是全站最孤立的一群頁面（內鏈是少數能把 `Discovered` → `Crawled` 推動的站內槓桿）。修法比照 `articles/[slug].astro`：手動 `relatedX` 全空時退到 `getAutoRelated()` 的 tag 重疊自動補齊，並加上 spoke→hub 膠囊。修完後絕大多數成分頁都有相關內容與專題回鏈。

剩下未覆蓋的頁多半是 tag 命中不到任何 hub，屬 `matchKeywords` 廣度問題，見下方「常見陷阱」。

#### ⚠️ 闢謠頁（myths）不套用這套

`myths/[slug].astro` 的版型是**刻意簡化**的（見 `docs/pitfalls.md`）：不得加「延伸閱讀」「更新與更正紀錄」「相關內容」這類**導覽**區塊。~~因此闢謠頁不加 `getAutoRelated()`~~ → **2026-08-07 已加上延伸閱讀**（理由與數據見 `../page-rules/myths.md`）。仍**不加**「所屬健康專題」膠囊——hub 連結維持 hub→spoke 單向（`/topics/<slug>/` 會自動收錄闢謠）與 tag 頁達成。

⚠️ **2026-08-06 釐清適用範圍**：這條規則擋的是「為 SEO／內鏈硬加的導覽區塊」，不是該篇自己的內容。當天經使用者授權新增了兩塊**內容**：FAQ（本就是刻意保留的例外）之外，再加「那，實際上該怎麼做？」（`safeActions`／`avoidActions`／`whenToSeekProfessionalAdvice`）。判準：**這個區塊的內容是這一篇獨有的、還是把站上別處的東西搬過來？** 前者可以討論，後者一律不加。

### 專題卡片縮圖（資料驅動，零手工維護）
- 專題**沒有**逐主題圖庫，也不維護 `topics.ts` 圖片欄位。`/topics/` 列表頁與首頁「健康專題」區塊的卡片縮圖，一律由 `resolveTopicCover(topic, [articles, ingredients])`（`src/utils/topic-cover.ts`）**從該主題自動歸入的文章／成分解析取一張封面**（各池先按發佈日新到舊排序，取第一個「有比對到本主題且封面合法」者）。
- 合法性判定與各 Card 一致：外連 `http(s)://` 直接採用、本地 `/…` 須 `public` 下存在；全數落空時退回品牌佔位 `/og-thumb/home.webp`（`alt=""`＋`aria-hidden`，視為裝飾）。
- 效果：新內容配好 `coverImage` 後，專題縮圖自動更新，不需手動指派。想換某主題的代表圖 → 讓一篇有理想封面的內容成為該主題「最新一篇」即可。

## 修改流程

### 新增一個主題
1. 在 `src/data/topics.ts` 的 `TOPICS` 陣列加一筆物件：
   - `slug`：語意化英文短語（= 網址 `/topics/<slug>/`）。
   - `name`：前台中文名稱（用「健康專題」語感，**不要**用技術詞「主題集群」）。
   - `intro`：1–2 句簡介（會進 meta description 與頁首）。
   - `thirtySecond`：3–5 點「30 秒重點」，每點能獨立成立。
   - `matchKeywords`：用來把內容歸入此主題的關鍵字（小寫，比對內容的 **title + tags**）。
   - `faq`：2+ 題自然的常見疑問（會輸出 FAQPage JSON-LD；規範見 content-guide「FAQ 撰寫規範」）。
2. `pnpm build`，確認 `dist/topics/<slug>/index.html` 有產出且各區塊**非空**。

### 內容如何被歸入主題
- 採**自動比對**，不需手寫 slug 清單：`matchesTopic()` 對每篇內容的 `title + tags`（myths 另含 `topicTags`）做關鍵字包含判斷。
- 想讓某篇文章進入某主題 → 在該文章 frontmatter 的 `tags` 補上該主題的關鍵字即可。
- 各區塊只在「真的有比對到內容」時渲染，避免空區塊。

## 常見陷阱
- **關鍵字太廣**會把不相關內容掃進來（例如單一個「鈣」字）。優先用較專一的詞，並以 `title + tags` 為比對範圍（不掃內文，降低雜訊）。2026-07-12 已把 `supplement-guide` 過廣的「行銷／誇大／偽科學」關鍵字移除（原本掃進 50+ 篇稀釋主題性），改留專一詞＋補「堆疊／交互作用」。
- **未來 publishDate / draft / under-review** 內容不會進主題頁（共用 `isPublicEntry`，見 `src/utils/visibility.ts`）。
- 新增主題後務必確認 sitemap（`dist/sitemap-0.xml`）有 `/topics/<slug>/`。

## 驗證清單
- [ ] `pnpm build` 零錯誤。

## 自動相關內容的推薦邏輯（`src/utils/related.ts`）

手動 `relatedX` 一律優先；全空時才走自動推薦。自動推薦分**三層**，上層湊得到就不動用下層：

| 層 | 條件 | 為什麼 |
|---|---|---|
| 1 罕見標籤 | 共享至少一個「出現在 ≤10% 候選頁」的標籤 | 最能代表在談同一件事 |
| 2 同健康專題 | 用 `matchesTopic()` 判定屬同一 hub | 標籤太碎時的主力訊號 |
| 3 泛用標籤 | 只共享泛用標籤 | 等同隨機推薦，最後手段 |

排序在層內用 **IDF 加權**：權重 `log(候選總數 / 該標籤出現篇數)`，泛用標籤趨近 0。

**為什麼要分層（2026-08-07 實測，改之前的數據）**

- 全站 860 個標籤中，**668 個只出現在 1 篇**，而「預防醫學」有 78 篇。舊算法只數「共享幾個標籤」，共享一個「預防醫學」和共享一個「褪黑激素」同分。
- 結果是文章頁 36% 的推薦連結只靠泛用標籤湊數。
- 只加 IDF 排序**沒有用**（實測反而是 40%）——因為那些候選還是會填滿版位，排序不改變它們出不出現。
- 加入專題層才是關鍵：108 篇已發布文章中，有 38 篇找不到任何共享非泛用標籤的同伴；改用專題後降到 21 篇，每篇候選數中位從 1 個上升到 14 個。

**改動後**：泛用湊數 36% → 20%，每頁對外連結約 2 個 → 5.3 個，其中 190 個來自專題層。

⚠️ 兩個判準寫在程式註解裡，改之前先讀：
- `GENERIC_DF_RATIO = 0.1`（泛用標籤的門檻）
- 「用不用下一層」在 **getAutoRelated 全頁層級**決定，不是分桶決定。分桶各留 1 個是不夠的——5 個桶就會漏 5 個泛用結果進來（實測 30%）。

**這個演算法的天花板在標籤品質**，不在程式。要再往上，得減少一次性標籤、讓同主題內容共用可辨識的標籤。

## 標籤同義詞收斂（2026-08-07）

`src/data/tag-aliases.ts` 是同義詞對照表，`scripts/normalize-tags.mjs` 把它套用到既有內容。

**為什麼要做**：全站 1044 個不重複標籤裡有 801 個（77%）只出現在一篇。標籤這麼碎等於沒有
標籤——既不能當推薦訊號，也不能當導覽。碎裂的主因不是題材真的那麼分散，而是同一個概念有
很多寫法：「心血管疾病 / 心血管保健 / 心血管 / 心血管健康」四個標籤分掉了 25 篇。

首輪收斂 81 個檔案、93 個標籤，1044 → 1002。成分頁站內出口中位數 4 → 5、趨勢 4 → 5。

**這張表只做同義詞收斂，不做語意分類。** 判準是「換個寫法讀者會不會覺得意思變了」：
「腸道菌相 / 腸道菌 / 腸道菌群 / 腸道菌叢」是同一件事的四種寫法，併；
「腸道菌相」和「腸道健康」是不同顆粒度，不併；「運動」和「運動營養」不併。

**收斂之後剩下的 765 個單次標籤不是同義詞問題**，是「氣炸鍋」「猴頭菇」這種真的只有一篇
在談的具體題材。再併下去會失真。所以推薦品質的解法不是繼續併標籤，而是上面的專題層——
標籤負責精準，專題負責覆蓋，兩者分工。

**為什麼改 frontmatter 而不是只在讀取時轉換**：`/tags/<tag>/` 的路由、`tag-stats` 的統計、
推薦演算法的 IDF 都直接吃 frontmatter。只在某一處轉換，其他地方看到的還是舊值，會出現
「推薦算得出來但 tag 頁分開」這種內部不一致。
